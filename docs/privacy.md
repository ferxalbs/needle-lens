# Needle Lens privacy note

Needle Lens is a BYOK, local-first browser extension. There is no Needle backend, account, analytics SDK, shared cache, or server-side lead database.

## What is read

After the user explicitly grants the two exact X host origins and requests a preview, the extension reads only rendered `article` elements on the active `x.com` page that are visible or immediately adjacent to the viewport. It extracts post text, a displayed author label when available, a canonical status URL for a local **Open on X** link, and viewport position. Promoted containers, duplicate status IDs, empty text, and non-X tabs are rejected.

## What can leave the browser

Only after the user sees the preview and presses **Send one decision request**, the service worker sends the goal, selected mode, and visible post text to `https://api.typesafe.ai/v1/systemone` in one request. The provider receives no API key as a field: the key is sent only in the HTTPS `Authorization` header from the trusted service worker. The key never enters page JavaScript, the content script, a URL, a receipt, or a provider request body.

The side panel identifies these fields before consent. The provider response is validated locally; policy reasons and highlights are generated by the extension. The extension never sends messages, posts, follows, clicks, scrolls, or DMs on the user's behalf.

## Retention and deletion

The API key, provider signals, cache, and session receipt use `chrome.storage.session`. Cache entries contain a SHA-256 key and normalized signals, not raw post text. The session is cleared by browser restart/extension lifecycle, **Forget key** removes only the key and fingerprint, and **Clear session** removes all session state. Authentication failure also removes the key. Receipts are exportable text and do not contain the key or raw provider payload.

The extension makes no claim of comprehensive X discovery. It judges only the posts already rendered for the user in the active session.
