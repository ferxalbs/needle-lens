# Needle Lens privacy note

Needle Lens is a BYOK, local-first browser extension. There is no Needle backend, account, analytics SDK, shared cache, or server-side lead database.

The X tab adapter is experimental and user-initiated. Needle Lens does not claim that reading rendered X content is approved, authorized, or compliant with X. Review the current [X Terms](https://x.com/en/tos) before use; X may require prior written permission for scraping.

## What is read

After the user explicitly grants the two exact X host origins and requests a preview, the extension reads only rendered `article` elements on the active `x.com` page that are visible or immediately adjacent to the viewport. It extracts post text, a displayed author label when available, a canonical status URL for a user-clicked **Open on X** link, and viewport position. Promoted containers, duplicate status IDs, empty text, and non-X tabs are rejected. The candidate set is bounded to the active Lens's 1–30 item limit; an empty set is shown as a recoverable state.

## What can leave the browser

Only after the user sees the preview and accepts the data-use notice, the service worker sends the Lens goal/criteria, selected mode and strictness, and visible post text for uncached candidates to the official TypeSafe `systemOne` endpoint in one request. The provider receives no API key as a field: the key is sent only in the HTTPS `Authorization` header from the trusted service worker. The key never enters page JavaScript, the content script, a URL, a receipt, or a provider request body.

The side panel identifies these fields before consent. The provider response is validated locally; policy reasons and highlights are generated by the extension. The extension never sends messages, posts, follows, clicks, scrolls, or DMs on the user's behalf.

## Retention and deletion

Session-only key retention is the default. If the user explicitly selects seven-day retention and the browser can persist a non-extractable AES-GCM key, Needle stores only an encrypted envelope, its expiry, and a short fingerprint in local extension storage; the raw API key is never stored there. If that structured-clone capability is unavailable, Needle falls back to session-only retention and tells the user. Expired envelopes are purged on worker startup and before settings/state reads. **Forget key** removes both session and remembered credential material.

Decision metadata can be retained **off**, for the current session, or for at most 24 hours. Cache entries contain a SHA-256 key and typed decision signals, not raw post text. Receipts contain Lens criteria, counts, latency, usage/cost metadata when supplied, and the local outcome, never the key or raw provider payload. **Clear cached decision metadata** removes cache and receipt state; **Clear all local Needle data** also removes saved Lenses, consent, settings, and credentials, restoring safe defaults on the next use.

The provider's own retention and training terms are not controlled by Needle Lens. Users should review the current [TypeSafe Privacy Policy](https://typesafe.ai/legal/privacy-policy) before sending data.

> TypeSafe retention terms were not verified by Needle Lens. Review TypeSafe’s current privacy policy before continuing.

The extension makes no claim of comprehensive X discovery. It judges only the posts already rendered for the user in the active session.
